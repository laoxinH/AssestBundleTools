## 2. 当前结论

当前 UI 正式采用下面这套主方案：

- 单主窗口承载主工作流
- `NavigationView` 作为应用外壳
- 工作台采用“左侧资源包列表 + 中间资源包标签页与资产列表 + 右侧资源详情检查器”的三栏布局
- 资源包浏览扩展能力统一通过类似 VS Code 的标签页实现，不再引入资源包浏览子窗口
- 资源详情后续可扩展为同一工作区进程内的独立资源编辑窗口，作为资产文档宿主增强而不是资源包浏览子窗口；详细见 [asset-editor-window-mode.md](asset-editor-window-mode.md)
- 工作区采用 IDE 式模型演进，允许登记多个工作区，但任意时刻只存在一个活动工作区
- 详细日志统一沉淀到“设置与诊断”，主工作区只保留轻量 toast 反馈

## 3. 设计原则

### 3.1 工具效率优先

当前界面必须优先支持：

- 快速切换资源包
- 快速浏览资产列表
- 快速查看当前选中资源的状态、替换信息与变更摘要
- 在不离开主工作区的前提下完成主要操作

### 3.2 风险操作显式化

提取、替换、保存都属于高风险或高价值操作，UI 需要保证：

- 不直接误触覆盖原始资源
- 替换状态清晰可见
- 批处理与保存前摘要有独立承载页
- 失败信息可追踪到“设置与诊断”

### 3.3 状态分层明确

状态必须严格分层：

- 工作区状态承载真实数据与变更队列
- 页面标签页只承载浏览状态
- 视图控件只负责显示与交互桥接

### 3.4 视觉方向统一

界面视觉继续遵循当前已经稳定下来的方向：

- Win11 设置风格的无边框与半透明背景氛围
- 卡片更紧凑、圆角更克制
- 左侧资源包列表参考 VS Code Explorer 的层级与选中反馈
- 中间资源包切换参考 IDE 标签页，而不是弹新窗口

### 3.5 多语言先行

所有用户可见文本继续通过 `.resw + ResourceKeys.cs` 管理，不允许重新出现硬编码文案。

## 4. 应用信息架构

当前一级页面固定为：

1. 控制台 / 工作台（同一导航入口按窗口态切换）
2. 批处理任务
3. 设置与诊断

各页面职责如下。

### 4.1 控制台

负责：

- 启动入口
- 最近工作区与最近操作占位
- 新建工作区入口
- 打开已有工作区与恢复最近工作区入口

### 4.2 工作台

负责：

- 工作区内资源包浏览
- 资源包标签页管理
- 资产列表筛选、搜索与多选
- 单资源检查、提取、替换与撤销

补充说明：

- 当前由 `BundleExplorerPage` 承载正式工作台
- 一级导航第一入口位在控制台态显示“控制台”，进入工作区后切换为“工作台”
- 工作台顶部提供 `返回控制台` 动作，便于重新整理工作区入口

### 4.3 批处理任务

负责：

- 当前活动工作区的变更摘要
- 批量提取预览
- 批量替换预览
- 保存前摘要与输出计划

### 4.4 设置与诊断

负责：

- 详细日志中心
- 环境与异常诊断
- 后续语言、主题与调试偏好设置

## 5. 工作台设计

当前阶段的核心工作页面由 `BundleExplorerPage` 承载。

### 5.1 顶部命令区

顶部入口与命令区当前保留：

- `新建工作区`
- `打开工作区`
- `返回控制台`
- `打开文件`
- `打开目录`
- `刷新`
- `批量提取`
- `保存为新包`

其中：

- `新建工作区 / 打开工作区` 通过状态标签前的轻量入口按钮承载
- `返回控制台` 用于当前窗口回到控制台页，不销毁已有活动工作区上下文
- `打开文件` 与 `打开目录` 先保留入口和位置
- 真实接入优先级低于当前的工作区机制完善与 AB 读取接入

### 5.2 状态摘要区

顶部命令区下方保留一行状态摘要卡片，采用标签化信息呈现，而不是长句堆叠。

当前建议显示：

- 当前工作区
- 资源包数量
- 资源数量
- 已登记工作区数
- 已打开标签页数
- 当前解密器
- 来源路径

### 5.3 左侧资源包列表

左侧区域当前负责：

- 资源包分组显示
- 展开式搜索框
- 当前资源包选中反馈
- 作为标签页的直接打开入口
- 在需要时收缩为摘要窄条

交互要求：

- 单击资源包项：直接打开或激活对应资源包标签页
- 不再提供额外的“新标签页”按钮
- 左侧列表始终保持 Explorer 风格，不再增加依赖树和二级切换页签
- 收缩按钮使用左右箭头表达“收起 / 展开”语义
- 收缩为摘要窄条时，只保留资源包数、分组数和当前选中资源包摘要
- 收起与展开过程采用列宽渐变配合内容淡入动画
- 收缩后中间资产列表与右侧检查器均分剩余横向空间

### 5.4 中间标签页与资产列表

中间区域由两部分组成：

- 资源包标签页栏
- 当前活动标签页对应的资产列表

标签页规则：

1. 同一工作区内同一资源包只保留一个标签页实例
2. 单击资源包列表是默认打开标签页的方式
3. 关闭标签页只回收页面级状态，不影响工作区数据

资产列表规则：

1. 保持表格型浏览样式
2. 支持搜索、类型筛选、仅已修改、仅可预览
3. 支持扩展多选
4. 当多选数量大于 1 时显示列表内快捷操作条
5. 当前快捷操作条只保留 `提取选中`
6. 资产类型筛选项由应用层资产列表结果提供当前资源包的可展示类型 Facet：`All` 固定第一，已知高价值类型按固定优先级显示，其他真实 Unity 类型按实际出现动态追加并显示数量，零数量类型不显示

### 5.5 右侧检查器

右侧检查器当前负责：

- 概览信息
- 预览占位
- 工作区替换状态
- 文件替换状态
- 变更摘要
- 固定在底部的快速操作按钮区

当前编辑入口统一收敛在这里：

- `提取`
- `工作区来源`
- `选择文件来源`
- `应用替换`
- `撤销`

### 5.6 即时反馈

主工作区中的即时反馈统一采用顶部浮动 toast：

- 成功反馈
- 高价值警告
- 明确失败结果

详细日志不再回到工作台页面内部。

## 6. 工作区与标签页关系

当前必须明确区分下面两层概念：

### 6.1 工作区

工作区是业务事实来源，负责：

- 已加载资源包
- 已加载资产摘要
- 已应用替换
- 提取记录
- 批处理摘要

### 6.2 标签页

标签页是页面级浏览状态，负责：

- 当前浏览的资源包
- 当前筛选条件
- 当前搜索条件
- 当前主选中资源

因此：

- 切换标签页不会创建新的工作区
- 关闭标签页不会丢失工作区变更
- 工作区切换时需要整体刷新标签页承载内容

## 7. 当前不纳入实现范围

以下内容不再作为当前阶段 UI 主方案的一部分：

- 资源包浏览子窗口
- 主界面双窗格对比
- 依赖树主工作流
- 跨标签页真实拖拽替换
- 完整工作区切换器 UI
- 全类型真实预览器

资源编辑窗口模式属于资源详情 / 编辑支线，已单独记录在 [asset-editor-window-mode.md](asset-editor-window-mode.md)，不等同于这里被淘汰的资源包浏览子窗口。

## 8. 后续优先级

当前 UI 相关的下一步重点不是再扩布局，而是继续补齐下面这些能力：

1. 文件导入 / 目录导入到工作区的真实接入
2. 真实 AB 读取接入后的界面刷新链路
3. 导入后标签页、筛选与工作区恢复信息的协同闭环
4. 多选提取、替换摘要与批处理页之间的协同闭环
5. 保存与输出阶段的用户确认体验

## 9. 执行结论

后续 UI 开发默认遵循以下结论：

- 主工作流固定在单主窗口内完成
- 资源包浏览扩展能力统一使用标签页
- 工作区和标签页必须保持职责分离
- 主工作区保持三栏结构，不再回退到多窗口方案
- 详细日志继续集中在“设置与诊断”
