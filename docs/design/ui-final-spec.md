# AssestBundleTools UI 收敛方案 V3

## 1. 文档目的

本文档用于记录当前阶段已经正式收敛的 UI 方案，作为后续开发、验收与讨论的统一基线。

当前文档只保留已经确认的主工作流，不再保留已经被淘汰的资源包浏览子窗口方案；资源详情后续允许演进为同一工作区进程内的独立资源编辑窗口，详细设计见 [asset-editor-window-mode.md](asset-editor-window-mode.md)。

补充说明：

- 本文是当前唯一继续维护的 UI 规范入口。
- 旧的 [ui-design.md](ui-design.md) 和 [ui-wireframes.md](ui-wireframes.md) 已合并到本文，只保留兼容入口，避免 UI 状态在多个文档中分叉。
- UI 相关下一步不再优先扩展新布局，而是围绕提取、替换、保存输出流程补顺操作入口、反馈、进度和结果明细。

## 2. 最终结论

当前 UI 采用“控制台页 + 主窗口单窗格三栏工作台 + 资源包标签页 + 多工作区上下文预留”的方案。

核心原则如下：

1. 主工作流固定在主窗口完成，不再为资源包浏览引入子窗口。
2. 左侧负责资源包浏览与搜索，中间负责标签页和资产列表，右侧负责资源详情与编辑入口。
3. 详细日志集中在“设置与诊断”，主工作区只保留轻量 toast 反馈。
4. 所有修改统一归属到工作区会话，不直接覆盖原始文件。
5. 工作区上下文按 IDE 式模型演进，允许应用登记多个工作区，但主任务始终绑定当前活动工作区。
6. 标签页只承载页面级浏览状态，工作区数据仍是唯一事实来源。
7. 控制台页默认在应用启动阶段显示；进入工作区后可继续停留在工作台，也允许通过显式按钮返回控制台。
8. 资源编辑窗口只作为工作台中的资产文档宿主扩展，不改变活动工作区、资源包浏览和变更队列的归属。

## 3. 应用结构

应用外壳继续使用 `NavigationView`。

其中一级导航当前保留三个稳定入口位：

- 第一入口位：无活动工作区时显示“控制台”，进入工作区后显示“工作台”
- 批处理任务
- 设置与诊断

主窗口底部保留一条全局信息条，形态参考 VS Code 式轻量状态栏：

- 常态显示应用当前状态，例如“就绪”。
- 当导入、批量提取等后台任务运行时，显示当前任务标题、正在处理的对象、确定性进度或不确定进度；工作区级批量提取应显示当前资源包 / 当前资源或 Spine 组、成功 / 失败计数，并在内存压力退避时给出短提示。
- 当存在多个后台任务时，状态条在当前任务旁显示后台任务数量；鼠标悬停在数量区域时直接显示 VS Code 式轻量悬浮面板，列出当前调度器会话内所有后台任务、状态、进度和可用取消入口，鼠标离开状态条数量区域与悬浮面板后自动关闭；数量区域不再叠加普通 tooltip，避免与任务面板的悬停触发竞争，同时应支持点击 / 键盘激活以打开同一面板。
- 状态条只承载轻量状态与进度，不替代 toast、日志中心或操作记录；任务完成后的成功 / 失败结果仍通过既有通知、日志和变更页展示。
- 状态条由 Shell 级服务维护，页面或操作 handler 只上报任务进度，不直接操作 Shell 控件。
- 状态条进度刷新必须按最新状态合并到 UI 线程，不能每个文件写出都直接排队一次 UI 更新；批量任务完成后的日志也应优先记录摘要，避免日志集合逐条插入导致主窗口短暂卡死。
- 后台任务的统一 profile、并发闸门、取消和状态条投影规则见 [background-task-scheduling.md](background-task-scheduling.md)；本 UI 文档只约束状态条的视觉与页面行为。

其中第一入口位复用同一个 `NavigationViewItem` 承载两种窗口态：

- 控制台态：默认在应用刚启动时显示，也允许从工作台显式返回
- 工作台态：进入活动工作区后显示正式工作台

当前控制台页承担以下稳定职责：

- 提供 `新建工作区 / 打开工作区 / 打开最近工作区` 三个快速入口
- 以固定高度面板展示 `工作区列表` 与 `最近操作`
- `工作区列表` 与 `最近操作` 各自使用卡片内滚动，不再让整页纵向滚动
- 允许从最近工作区列表删除登记记录
- 当“启动时恢复上次工作区”设置开启且上次活动工作区仍可用时，允许启动后直接恢复到正式工作台
- 新建 / 打开工作区时使用单一可视化配置面板，而不是连续目录选择器
- 工作区向导中允许单独配置工作区名称，并把该名称保存到工作区元数据和最近工作区列表
- 新建工作区时先创建空工作区，不再要求预先指定 AB 来源目录；资源后续通过拖拽或导入入口加入
- 从控制台再次打开最近工作区时，支持三种设置策略：默认复用当前窗口、默认新建窗口、每次询问
- 当策略为“默认新建窗口”且目标工作区已在某个主窗口中打开时，直接激活已有窗口，不再重复创建新窗口

当前工作台页面由 `BundleExplorerPage` 承载，并在状态标签前置动作区同步承担以下工作区入口职责：

- `新建工作区` 复用与控制台页一致的可视化工作区向导
- `打开工作区` 复用已有工作区打开向导
- `返回控制台` 允许当前窗口回到控制台页，而不强制关闭现有活动工作区上下文
- 页面直接从导航进入时优先恢复当前活动工作区，而不是回退到独立的示例数据入口

## 4. 工作台最终结构

当前工作台页面采用“三栏固定工作区 + 顶部命令区 + 顶部浮动提示”的结构。

### 左侧

左侧为资源包列表，负责：

- 显示当前工作区中已加载的资源包分组
- 提供 VS Code 风格的 explorer 式浏览体验
- 在列表标题栏提供 `文件导入 / 目录导入` 入口
- 支持把资源包文件或目录直接拖到左侧资源包列表区域触发导入提示层
- 提供资源包搜索和过滤入口
- 作为资源包标签页的直接打开入口
- 资源包项支持右键上下文菜单，至少提供 `打开所在位置` 与 `从工作区移除`
- 支持收缩为摘要窄条，以释放更多横向空间给资产列表与资源详情
- 当工作区尚未导入任何资源包时，显示“空工作区”专用空状态提示，而不是误导性的“未打开标签页”提示

当前阶段不再显示独立依赖树主窗格。

但工作台右侧检查器应提供单独的“依赖”页签，以列表方式承载：

- 资产级依赖
- 反向引用
- 依赖闭包
- Bundle 外部依赖

补充规则如下：

1. 资产依赖项应展示友好资源名、所属资源包摘要、`PathId` 与必要的类型信息。
2. 依赖闭包项应额外展示闭包深度，便于判断某个资源是直接依赖还是间接依赖。
3. Bundle 外部依赖应优先展示友好名称和依赖类型；对于 `archive:/CAB-xxx/CAB-xxx` 这类引用，如当前工作区能反查到对应资源包，则标题优先显示具体 `xxx.ab` 文件名，并在副标题保留 `CAB-*` 标识，同时把原始引用路径作为补充信息保留。
4. 友好路径解析优先采用 Unity `m_Container` 路径，缺失时再回退到 `SerializedFileName / 资产类型 / PathId` 组合摘要，避免同名资源在依赖页中难以区分。
5. 已解析到当前工作区资产身份的依赖项应提供“打开资源”入口，并复用右侧资产文档标签链路跳转到目标详情。`PathId` 继续作为 Unity 对象定位信息展示，但实际跳转键使用 `BundleId + AssetId`，避免跨 Bundle / 外部 CAB 中同 PathId 资源误跳。

同一套 `文件导入 / 目录导入` 入口应同步承载到批处理页和“设置与诊断”页的活动工作区摘要区，避免后续真实导入链路在不同页面出现分叉。
工作台中的拖拽接收范围当前应限制在左侧资源包列表区域，不扩散到整页，给后续资产列表拖拽操作保留清晰边界。

左栏收缩后的摘要窄条当前保留：

- `文件导入 / 目录导入` 的文字标签按钮
- 当前可见资源包总数
- 当前可见分组数量
- 当前选中资源包的短缩写与完整悬浮提示

当左栏收缩时，中间“资产列表”和右侧“资源详情”需要均分释放出来的横向区域。

### 中间

中间区域由“标签页栏 + 当前活动资产窗格”组成，负责：

- 显示当前已打开的资源包标签页
- 显示当前活动资源包的资产列表
- 提供搜索、类型筛选和本地显示筛选
- 支持鼠标友好的多选
- 在多选状态下显示列表内快捷操作

当前收敛规则如下：

1. 资产列表默认保持单表格浏览样式。
2. 资产列表支持 `Ctrl / Shift` 扩展多选，也支持通过行右键菜单显式进入多选模式。
3. 进入多选模式后，普通单击行项只负责加入 / 移除当前多选集合，不触发资源详情标签切换，也不重置当前列表滚动位置；按住左键并划过多行时，划过已选中项会取消选择，划过未选中项会加入选择；按住左键期间使用滚轮滚动列表时，选区应按列表顺序连续切换到滚动后鼠标所在行，避免高速滚动留下断层；退出多选后恢复普通单击打开 / 激活资源详情的行为。
4. 多选模式下在列表头部下方显示快捷操作条，使用与资产列表工具栏一致的图标按钮样式，提供 `退出多选`、`全选`、`反选`、`提取选中`。其中 `提取选中` 必须先让用户选择批量提取目标目录，再对当前多选集合逐项执行真实提取，不使用隐式默认输出目录；普通资源批量提取的输出结构为 `<输出根目录>/<AB 资源包名称>/<资源类型>/<文件名>`。多选批量提取的真实写出循环应在后台任务中执行，并通过 Shell 底部信息条显示任务进度，避免资源较多时阻塞列表滚动、标签切换和窗口交互。
5. 普通资源行和 Spine 组行都支持与资源包列表一致的右键上下文菜单样式：`在新窗口中打开`、`提取`、`修改`、`进入多选`。右键命令应先把目标行同步为当前列表焦点，再复用统一资源文档标签 / 独立资源编辑窗口 / 提取 / 修改命令链路；`进入多选` 只扩展当前列表选择，不改变右侧已打开的资源详情标签。普通资产右键 `修改` 与资源详情操作区 `修改` 属于同一文件来源修改入口：发起新修改时，当前支持文件替换的 `Texture2D` 应打开文件选择器选择图片来源并立即应用为新的 `ReplaceFromFile` 操作；该快捷入口不把工作区来源作为兜底，工作区来源只保留在已有显式工作区来源入口中。Spine 组右键 `修改` 与组文档操作区 `修改` 属于同一编辑入口：打开或激活独立资源编辑窗口并进入 Spine 组成文件替换装配台。
6. 单资源提取仍保留在右侧检查器中。Mesh 单资源提取的保存文件对话框提供 `OBJ / FBX` 格式切换，其中 FBX 当前只承载静态几何、UV0 和三角面，复杂材质、骨骼、蒙皮与动画不进入第一版导出。MonoBehaviour 单资源提取默认写出 `TypeTree JSON` 字段树，并在保存文件对话框中额外提供摘要 JSON、YAML 投影和原始字段清单文本；TypeTree JSON 来自 Infrastructure 读取到的 Unity 字段树，摘要 / YAML / 字段文本仍是基于当前预览 DTO 的可读投影，不伪装成 Unity 原始二进制对象。
7. 每个资源包标签页都应独立保存资产列表的搜索条件、类型筛选、本地显示筛选和当前选中资源。
8. 切换资源包标签页时，资产列表应恢复到该标签页上次浏览状态，不因切换而丢失当前选中资源。
9. 应用重启后，如果工作区恢复了已打开标签页，则活动标签页的资产列表也应自动恢复到上次选中的资源。
10. 每个资源包标签页下的右侧资产详情区应再提供一层“资产文档标签”，用于并行保留多个资源的详情上下文，而不是只复用单一检查器实例。
11. 资产文档标签需要独立保存当前资源、当前检查器页签和页面级候选状态；切换资源包标签页或重启应用后都应尽量恢复。
12. 资源包标签与资产文档标签都应支持拖拽重排；重排只改变当前工作区内的页面级浏览顺序，不改变底层资源数据语义。
13. 标签拖拽重排后的顺序需要进入工作区浏览状态持久化，切换资源包标签、返回控制台再进入以及重启应用后都应尽量按上次顺序恢复。
14. 资产文档标签后续需要支持类似 VS Code 的窗口模式：单个资产文档标签可以拖出为独立资源编辑窗口，主窗口右侧的整个资源详情窗格也可以拖出为独立资产文档组；多个独立窗口之间可以通过拖拽资产文档标签组合成新的标签页组，也可以把标签或整个组重新放回主窗口。
15. 资源列表的搜索、类型筛选和本地显示筛选只影响当前列表结果与焦点恢复，不应直接关闭已经打开的资产文档标签；即使当前筛选结果为空，右侧已打开的资产详情标签也应继续保留，同时列表也不应自动把焦点跳到筛选结果第一项。
16. 当筛选变化并未改变当前激活的资产文档标签时，右侧详情内容应直接复用现有状态，不重复触发详情查询、图片预览重载或详情页滚动位置重置。
17. 资源包标签与资产文档标签都应支持右键菜单，至少提供 `关闭其他` 与 `关闭全部`，并保持关闭后的焦点落点可预期；资产文档标签还应提供 `在新窗口中打开`、`移动到主窗口` 和后续 `移动到其他资源编辑窗口` 入口。
18. 资产列表搜索入口应与左侧资源包搜索保持一致，采用顶部图标按钮展开/收起搜索框的交互，不长期占用垂直空间。
19. 资产列表顶部不再额外显示“当前 Bundle”文字说明，类型筛选与本地显示筛选统一使用紧凑分段按钮样式，避免与上层标签条视觉重复。
20. 资产列表表头与数据行必须共享同一列布局并保持左对齐；名称列在截断时需要支持悬浮查看完整名称，整体字号应保持紧凑，优先为同屏显示更多资源信息服务。
21. `Spine` 不作为 `全部类型` 下拉中的 Unity 资产类型项，也不作为 `仅已修改 / 仅可预览` 同级的布尔筛选。当前资产列表工具条已提供独立的 `资源 / Spine 组` 视图切换；普通资源视图继续展示真实 Unity 资产、类型筛选和本地显示筛选，Spine 组视图展示由 `.atlas + .skel/.json + Texture2D` 组成的聚合条目摘要。搜索在普通资源视图中匹配资产名，在 Spine 组视图中匹配组名、skeleton、atlas 与 texture page 名；Spine 组选择会在右侧复用现有资源详情窗格打开组文档，组文档使用 `BundleId + GroupId` 或等价身份，并通过 Application 预览管线回填 atlas page / region 数量。普通资产文档和 Spine 组文档共享同一个外层资源文档标签栏，Spine 组标签头必须提供非文字视觉标识，不能只依赖标题文本区分。

### 右侧

右侧为资源详情检查器，负责：

- 外层承载当前资源包下已打开的资产文档标签
- 详情信息与预览承载
- 工作区替换来源与状态
- 变更记录
- 固定在底部的快速操作按钮区

当前编辑入口继续统一收敛在右侧检查器，不分散到其他区域。

右侧结构约束补充如下：

1. 外层 `TabView` 用于切换不同资产文档。
2. 内层检查器当前收敛为 `详情 / 依赖 / 替换 / 变更` 四页签；其中“详情”页统一承载预览画面、基础信息、预览补充信息与预览诊断，避免旧版“概览 / 预览”之间的信息重复。其视觉上应采用比外层文档标签更轻的分段切换样式，避免与上层大标签混淆；字体、高度和选中反馈都应明显更轻，作为次级内容切换而不是第二层文档标签。
   详情页中的文本信息区应进一步收敛为“标题 + 紧凑可折叠信息卡”结构，基础信息、预览补充信息和预览诊断使用统一卡片模型承载；卡片头部支持图标化复制动作，布局密度参考 Win11 设置页，但要比系统设置更紧凑，以适配 AB 资源较高的信息密度。当前信息卡已抽为可复用 `InspectorInfoCardView`，类型专属预览若需要把详细字段下放到详情区，应优先复用同一卡片模型。对 `AudioClip` 这类存在强操作性的资源，详情页顶部允许先给出一块独立的“工具型预览面板”，优先展示试听、容器、时长、声道、采样率、载荷来源与制作提示，再把完整字段保留给下方统一信息卡。
3. 资产文档标签归属当前工作区运行时会话和对应资源包浏览上下文；窗口模式只移动展示宿主和页面级浏览状态，不把资产文档升级为新的工作区实体，也不改变底层资源、替换队列或保存队列的归属。
4. 内层分段切换条需要保持紧凑，与上方资产文档标签和下方详情内容之间的留白应控制在次级导航应有的密度，不应出现明显断层。
5. 修改阶段的详情预览显示当前有效内容，而不是静态原始载荷：应用替换或草稿后，图片、Sprite 裁切、Mesh 贴图叠加、Material 引用缩略图、Spine 组 atlas / texture page / 动画播放等富预览都应同步刷新为替换后的结果。当前 `Texture2D` 已支持文件来源和工作区来源的有效图片预览；`Sprite` 已支持保存裁切框 / pivot 几何并用当前有效几何刷新预览。当 Sprite 关联 Texture2D 的有效图片尺寸与原贴图不同，Sprite 预览和编辑态应以有效图片真实像素尺寸作为源图画布，裁切框继续按 Sprite 几何显示和编辑，不把替换图片压缩到原画布尺寸。`Spine` 修改第一阶段作为资源组替换装配台，编辑态预览应使用“原始组 + 当前未保存组成文件草稿”即时生成；保存后再使用工作区操作记录物化出的 skeleton、atlas 和 texture page 有效载荷重新生成。后续类型应复用同一“操作记录 -> 有效读模型 -> 预览管线”链路。基础信息卡仍展示目标资产的原始身份、Bundle、PathId、Unity 类型和导入索引信息；替换来源、有效预览来源和待保存状态在 `替换 / 变更` 分段或预览补充信息中表达，不把原始信息悄悄改成来源资产信息。
6. `变更` 分段应展示独立操作记录卡片，而不是把文件修改和提取时间拼成一条摘要。`ReplaceFromFile / ReplaceFromWorkspace` 作为修改记录逐条展示；同一资产再次修改时追加新的修改记录。`ExtractAsset` 在资源详情中只展示最近一次提取记录，避免反复提取把修改历史冲散。卡片需要明确显示记录类型、来源、时间和状态标签：只有当前实际生效的替换记录显示“撤销”，其他替换记录显示“重做”，提取记录不和修改记录混用。记录卡片的动作按钮采用轻量标签化按钮；删除记录入口只删除工作区操作记录并触发读模型重放，不删除用户输出文件。操作记录保留上限在“设置与诊断”中调整，默认用于防止 `operations[]` 无限增长。
7. `Sprite` 修改第一阶段不复用 Texture2D 的文件快捷替换入口作为默认行为。用户从主窗口资源列表或检查器点击 `修改` 时，应直接打开或激活资源编辑窗口并进入 Sprite 编辑模式；窗口模式下源图预览锁定为带少量安全边距的自适应视口显示，不提供缩放、平移或裁切结果切换，用户通过鼠标拖拽裁切框移动 / 缩放，并可拖拽 pivot 定位点。若 Sprite 当前有效底图来自关联 Texture2D 替换，编辑态显示该替换贴图的完整真实像素画布，方便按新图调整裁切参数。编辑态顶部预览工具栏应提供一键复位原始 Sprite 参数、一键全尺寸裁切和替换关联 Texture2D；复位恢复预览载入时的原始裁切 / pivot，且全尺寸将整张源图作为裁切区域并沿用当前 pivot 相对裁切框比例；替换关联 Texture2D 选择图片后立即复用 Texture2D 的文件替换链路应用修改、追加 Texture2D 变更记录并通过关联影响刷新 Sprite 预览，不等待“保存 Sprite 编辑”。pivot 必须自动夹在当前裁切框内部；裁切框通过拖拽或数值输入变化时，pivot 应按当前记录的相对裁切框比例自动跟随，拖动框内部移动时裁切框和 pivot 一起平移；当用户手动拖拽或输入 pivot 坐标后，应重新记录新的相对比例，供下一次裁切框变化使用。拖动裁切框边 / 角时未参与拖动的边保持原位，拖动点时对角点保持固定，拖动边时对边保持固定。裁切框 X / Y 只限制最小值为 0，宽 / 高只限制最小可操作尺寸，不应因当前宽高接近源图尺寸而被最大值夹取锁定或移动锚点。拖拽会话开始后应冻结当前源图到视口的投影基准，窗口尺寸或布局变化只在拖拽完成后应用，避免窗口模式动态测量导致固定锚点抖动；编辑态裁切框应使用独立边线投影固定边 / 对角点，避免依赖 `Left + Width` 这类组合绑定造成视觉滑移。编辑态在预览框下方、功能按钮上方显示独立数值面板，展示当前裁切框与 pivot 的源图坐标数值，拖拽时实时刷新，手动修改裁切框数值时 pivot 按相对比例同步更新预览框，手动修改 pivot 数值时同步更新预览框并刷新相对比例；拖拽开始时应实际退出数值输入编辑态，释放数值输入框的编辑焦点和文本选区，拖拽期间数值面板只能展示当前拖拽结果，程序化字段刷新不得反向写回裁切几何，且数值面板不得覆盖预览画面。预览框内可显示轻量坐标轴、四个角点坐标和四条边长度数值，用于直观看到几何变化。窗口操作区在编辑态只显示保存、退出、撤销、重做四个轻量命令；保存仅在当前几何相对上次保存基线存在未保存修改时启用，保存后只追加 `EditDraftApplied` 几何操作记录并刷新有效预览；退出若存在未保存几何则提示保存或丢弃；用户直接关闭资源编辑窗口或关闭处于 Sprite 编辑态的资源标签时同样复用该提示，保存或丢弃后退出编辑态回到预览状态，再继续关闭窗口、关闭标签或放回主窗口，取消则保持编辑态并取消本次关闭；撤销和重做只按时间顺序重放当前编辑会话内的临时几何历史，最多保留 20 步，不提前写入工作区操作记录。保存生成的记录在 `变更` 分段以独立卡片展示，删除记录只重放工作区操作事实流，不删除原始 AB 或预览缓存。真实 AB 写入仍按 [workspace-recoverable-operation-records.md](workspace-recoverable-operation-records.md) 的保存 / 重建链路后续统一消费。

#### 资源编辑窗口模式

资源详情的窗口模式用于承接后续编辑、替换和对比工作。它不是新的工作区打开方式，而是同一活动工作区进程内的次级资源文档宿主；一个工作区仍由一个主进程承载，独立资源编辑窗口共享同一运行时会话、预览缓存、依赖图和变更队列。

完整的窗口模式术语、状态模型、拖拽规则、架构边界、实施阶段和测试建议见 [asset-editor-window-mode.md](asset-editor-window-mode.md)。本节只保留 UI 结构与主交互约束。

资源编辑窗口的基础形态如下：

1. 左侧为固定显示的“预览 / 编辑区域”，窗口模式下不再把预览区折叠进 `详情` 页签内部。图片、Mesh、文本等强视觉资源在这里提供主要操作面；结构化摘要资源也在这里显示主要摘要和轻量编辑入口。默认窗口高度下应优先保证该区域有可见画布，编辑附属区不得把预览视口挤到不可见。
2. 左下为功能区，承载当前资源的高频动作和编辑上下文。功能区采用与主窗口检查器一致的轻量标签式按钮，不再用独立卡片边框包裹整组命令。普通预览态只保留 `提取 / 修改` 这类高频入口；替换应用、操作记录撤销 / 重做和删除继续由右侧 `替换 / 变更` 分段承载。Sprite 编辑态只显示 `保存 / 退出 / 撤销 / 重做`，保存仅在有未保存几何时启用，退出在有未保存几何时确认保存或丢弃，撤销和重做只作用于当前编辑会话内最多 20 步的临时几何历史。Spine 编辑态同样只显示 `保存 / 退出 / 撤销 / 重做`，组成文件选择和批量匹配放在预览下方独立替换区，保存时才把草稿拆分为真实组成资产替换记录。窗口宿主搬运命令不再常驻在该功能区中；`移动到主窗口 / 全部移动到主窗口 / 在新窗口打开` 继续由拖拽、标签上下文命令和关闭策略承载。危险或不可用动作必须保持禁用、确认或诊断说明，不和普通视图工具混淆。
3. 右侧为信息区，继续使用 `详情 / 依赖 / 替换 / 变更` 的轻量分段切换。这里展示基础字段、预览补充信息、依赖导航、替换候选、变更摘要和诊断信息；它不是可拖拽资源文档标签的同级标签。
4. 顶部承载统一资源文档标签组。单个资源编辑窗口可以包含一个或多个普通资产文档或 Spine 组文档；拖入其他资源文档后形成独立窗口标签页组。标签组内的关闭、关闭其他、关闭全部、重排和激活规则应与主窗口右侧资源文档标签保持一致。
5. 独立资源编辑窗口的关闭行为由“设置与诊断”中的资源编辑窗口关闭方式控制：默认关闭标签或窗口时先回到主窗口，用户也可以切换为直接关闭。若当前活动 Sprite 处于编辑态，关闭窗口前必须先复用退出编辑的未保存确认；保存或丢弃后退出编辑态并回到预览状态，再按关闭偏好继续，取消则保持编辑态并取消关闭。关闭独立窗口内的单个资源标签时同样适用：若目标标签处于 Sprite 编辑态，先激活该标签并完成保存 / 丢弃 / 取消确认，确认继续后再放回主窗口或关闭标签。工作区切换、进程退出和拖拽空组清理这类内部生命周期关闭不受该偏好影响，必须直接关闭。

拖拽与合并规则如下：

1. 可拖拽对象分为两类：资产文档标签，以及整个资产文档组。内层 `详情 / 依赖 / 替换 / 变更` 分段不参与拖出、合并或跨窗口移动。
2. 从主窗口拖出单个资产文档标签时，新建一个资源编辑窗口，并只迁移该资产文档的页面级状态，包括当前检查器页签、预览浏览状态、替换候选选择和未提交的编辑草稿标识。
3. 从主窗口拖出整个资源详情窗格时，新建一个资源编辑窗口，并迁移当前资源包标签页下已打开的资产文档标签组、激活资产文档和组内顺序；主窗口右侧进入空组或保留占位态，由实现阶段根据交互细节决定。
4. 从独立窗口拖动标签到另一个独立窗口时，目标窗口把它插入目标标签组；源窗口若没有剩余标签，应自动关闭或显示空态。
5. 从独立窗口拖回主窗口时，资产文档重新归入对应资源包标签页下的主窗口资产文档组；如果主窗口当前未激活对应资源包标签页，应先打开或激活该资源包标签，再插入资产文档。
6. 资产文档组之间移动时，普通资产文档使用 `BundleId + AssetId` 作为唯一跳转和恢复键，Spine 组文档使用 `BundleId + GroupId`；`PathId` 只作为 Unity 对象定位信息展示，不作为跨 Bundle 移动的唯一身份。

窗口模式的状态归属规则如下：

1. 工作区级事实仍然只有一份：已导入资源包、资产索引、依赖图、预览缓存、替换队列、变更队列和保存计划不随窗口复制。
2. 资源编辑窗口只保存页面级展示状态：窗口位置 / 大小、所在显示器、标签组顺序、当前激活资产、内层分段位置、预览缩放 / 平移 / Mesh 工具栏状态、编辑草稿标识和替换候选选择。
3. 编辑草稿应绑定资产文档身份和工作区会话，而不是绑定 WinUI 控件实例；窗口关闭时若存在未应用草稿，必须进入确认或恢复队列，不允许静默丢失。
4. 多窗口同时展示同一资产时，替换队列和已应用变更以工作区状态为准；各窗口需要通过共享协调器接收刷新，不允许各自维护互相冲突的替换结果。
5. 窗口恢复优先恢复主窗口资源包标签和资产文档组；独立资源编辑窗口的恢复可以作为后续增强，在实现前不阻塞主工作区恢复。

建议分阶段实现：

1. 第一阶段：支持资产文档标签通过命令 `在新窗口中打开` 独立成资源编辑窗口；独立窗口内可打开多个资产文档并形成自己的标签组；支持 `移动到主窗口`。
2. 第二阶段：支持拖拽单个资产文档标签在主窗口和独立窗口之间移动，并支持独立窗口之间互相合并标签。
3. 第三阶段：支持拖出 / 放回整个资源详情窗格，恢复独立资源编辑窗口的位置、大小和标签组顺序。
4. 第四阶段：在编辑能力稳定后补充多窗口编辑冲突提示、草稿恢复、窗口间对比和差异确认，不提前把真实写包、冲突解决或回滚语义写死到 UI 层。

预览区后续按以下多形态承载演进：

预览窗格外层高度按资源形态区分：`Texture2D / Sprite` 图片视口、`Mesh` 渲染视口和 `TextAsset / Shader` 文本视口使用可配置固定高度，保证滚动和操作区稳定；`Material / Font / AnimationClip / GameObject / MonoBehaviour / AnimatorController` 等卡片式摘要预览交给内容自适应高度，避免短摘要留下大块空白，也避免长摘要被固定框裁切。

1. 图像预览
   - 用于 `Texture2D`、`Sprite`，后续扩展到 `SpriteAtlas`。
   - 当前图片视口支持按钮缩放/重置、鼠标拖拽平移和滚轮缩放；`Sprite` 源图裁切预览和裁切结果视图共享同一套观察状态，并把缩放/平移作为资产详情标签页的轻量浏览状态恢复。
   - 当前 `Sprite` 修改入口在资源编辑窗口内提供第一版裁切框 / pivot 编辑工作面：编辑态锁定源图为带少量安全边距的自适应显示，禁用普通图片缩放和平移，裁切框支持拖动移动、边 / 角缩放；顶部预览工具栏提供复位原始参数、全尺寸裁切和替换关联 Texture2D，前者恢复初始裁切 / pivot，全尺寸把整张源图作为裁切区域且保留当前 pivot 相对比例，贴图替换选择图片后立即应用到关联 Texture2D。贴图替换触发有效预览刷新时，只更新底图与画布尺寸，不重置当前编辑会话中的未保存裁切 / pivot 临时几何、保存基线和撤销 / 重做历史。拖动边时对边固定，拖动点时对角点固定，裁切框 X / Y 只做非负限制，宽 / 高只限制最小可操作尺寸。拖拽期间暂缓应用窗口尺寸或布局变化带来的视口更新，并继续使用拖拽开始时冻结的源图到视口投影基准，拖拽结束后再刷新投影，保证独立窗口动态布局下的固定边 / 对角点稳定；编辑态裁切框边线应独立投影，避免固定边由组合属性重算造成视觉滑移。pivot 支持拖动定位并自动夹在当前裁切框内部；裁切框变化时 pivot 按当前相对裁切框比例自动跟随，手动拖动或输入 pivot 坐标会刷新该相对比例。预览框内显示轻量坐标轴、四个角点坐标和四条边长度数值，预览框下方的独立数值面板展示并允许编辑裁切框和 pivot 源图坐标，和预览框保持双向同步且不覆盖预览；拖拽开始时实际退出数值输入编辑态并释放焦点，拖拽期间数值面板只展示当前拖拽结果，不得因程序化字段刷新反向写回裁切几何。几何编辑通过窗口操作区的“保存 Sprite 编辑”追加可恢复操作记录，保存按钮只在有未保存几何时启用；窗口操作区同时提供退出、撤销和重做，退出使用返回预览语义图标并负责未保存确认，撤销 / 重做只处理当前编辑会话内最多 20 步的临时几何历史。最终 AB 写入仍由后续保存 / 重建链路统一消费。
2. 文本预览
   - 用于 `TextAsset`、`Shader`。
3. 音频预览
   - 预留给 `AudioClip`，目标形态为 `播放 / 暂停 + 时长 + 波形或幅度摘要`。
   - 当前第二阶段已落地 `播放 / 暂停 + 基础音频信息`，并补上容器识别、外部转码与摘要回退；其中 `FSB5` 会优先转为标准 `WAV` 后播放，波形或幅度摘要仍保留为后续扩展。
   - 当前默认布局不再直接裸露系统播放器，而是采用紧凑工作卡：卡片首屏只保留资源名、原始大小与预览大小摘要，以及容器 / 时长 / 声道 / 采样率四个关键标签，中部承载播放器；更细的载荷来源、转码器与兼容字段继续放在下方统一信息卡中，避免首屏信息过载。
4. 模型预览
   - 用于 `Mesh`，当前形态为 `线框视口 + 逐三角贴图开关 + Mesh/UV 网格显隐开关 + UV0 视图切换 + 鼠标拖拽旋转 + 滚轮或按钮缩放 + 重置`；UV0 视图只在 DTO 携带 UV 坐标时显示切换入口，网格显隐只在当前视图已有可显示贴图时显示。
   - 模型视口只消费 Application 预览 DTO 中的轻量几何、三角面索引、UV0 和通道摘要，不直接读取或解析 AB；无法取得可渲染几何时继续回退结构化摘要。
   - 贴图关联提示优先消费详情 DTO 的 `TextureAssociations`：该字段由运行时工作区依赖图从 `Mesh <- MeshFilter / Renderer / ParticleSystemRenderer / GameObject -> Material -> Texture2D / Sprite` 主路径派生，只有主路径为空时才兜底使用 `Mesh -> Texture2D / Sprite` 直接依赖。
   - 贴图按钮在 UV 视图中表示把首个可预览关联贴图叠加到 `[0,1]` UV 空间，便于检查 UV 展开；在线框视图中若 DTO 同时具备三角面索引和 UV0，则表示按三角裁剪并使用 UV 仿射映射贴图，再叠加线框结构。网格按钮用于在线框视图隐藏或恢复边线、顶点与轴线，在 UV 视图隐藏或恢复 UV 单位格、UV 边线与顶点，方便只观察贴图映射后的外观；贴图缺失、贴图关闭或贴图位图尚未加载完成时仍保留结构层，避免空白预览。当前不模拟 Shader、Material tiling/offset、多材质 submesh 分配或光照效果，缺少三角 / UV / 可预览贴图时稳定退回纯线框。
5. 结构化 / 半可视化摘要预览
   - 继续作为 `Material / Font / AnimationClip / GameObject / MonoBehaviour / AnimatorController` 等类型的安全回退。
   - `AnimationClip` 当前自适应摘要预览区只展示资源名、时长 / 采样率 / 帧数、曲线数量、binding 摘要和事件概览；时间、循环、曲线 binding 与事件明细进入下方通用信息卡，避免预览框内信息过载。packed generic binding 的 keyframe 数在未解码前按未知展示，不显示为 0。
   - `GameObject` 当前自适应摘要预览区只展示资源名、激活 / Layer / Tag、组件摘要、Transform 摘要、层级摘要，以及组件构成 / 引用状态 / 常见组件专属字段的紧凑摘要卡片；对象基础字段、Transform 坐标 / 父子关系、组件 PPtr / 类型 / 脚本 / 启用状态，以及常见组件的 `Mesh / Material / Sprite / Controller / Avatar / AudioClip / Script` 引用明细进入下方通用信息卡。若这些 PathId 已被详情依赖图解析到当前工作区资产，信息卡行会复用统一“打开资源”链路；该预览仍属于轻量信息浏览，不做场景渲染或 Prefab 实例化。
   - `MonoBehaviour` 当前自适应摘要预览区只展示资源名、脚本摘要、启用状态、字段数、字段分组数和引用数等主要信息，并用紧凑摘要卡片补充脚本、字段和引用状态；对象基础字段、MonoScript 信息、字段分组、常见 Unity 序列化容器、前若干标量 / 数组字段、PPtr 引用明细和 TypeTree JSON 字段树进入下方通用信息卡。若 MonoScript 类名无法从当前导入资源中解析，只显示未解析脚本 PathId，不猜测脚本业务名；若脚本或字段引用 PathId 已被详情依赖图解析到当前工作区资产，信息卡行会复用统一“打开资源”链路；TypeTree JSON 来自预览 DTO 并支持复制完整字段树，但该预览仍属于轻量信息浏览，不做脚本业务语义推断、编辑或运行时模拟。
   - `AnimatorController` 当前自适应摘要预览区只展示资源名、Layer / Parameter、状态 / 转场和引用状态等主要信息，并用紧凑摘要卡片补充参数类型、状态机容器和引用解析情况；Layer、Parameter、`m_Controller` 常量区容器摘要和 `m_AnimationClips` 等 PPtr 引用明细进入下方通用信息卡。若引用 PathId 已被详情依赖图解析到当前工作区资产，信息卡行会复用统一“打开资源”链路；该预览仍属于轻量信息浏览，不做状态机画布、条件表达式编辑或运行时播放模拟。
6. Spine 资源组预览
   - 面向 2D 游戏常见的 Spine 资源组合，当前目标已经从 `资源组识别 + Atlas region overlay + 引用跳转 + 结构化诊断` 扩展到实验播放、真实 skin 切换和官方 runtime adapter 采样；高性能播放体验继续按 GPU 批量渲染路线推进，但产品范围只保留基础播放、动画 / skin 切换、进度 / 速度控制、预览视口平移 / 缩放 / 重置和导出基础，不追完整 Spine 查看器能力。
   - Spine 资源组属于跨资产聚合视图，不改变单个 `Texture2D / TextAsset` 的基础预览能力，也不伪装成新的 Unity 资产类型。打开资源组后，右侧检查器展示 skeleton、atlas、texture page 的匹配状态、skeleton 的轻量结构计数、当前已解析的 atlas page / region 数量、runtime adapter 状态、可用动画 / skin 播放入口，以及缺失 page、命名不匹配、atlas 预览不可用、外部引用未解析等诊断；更细的约束、linked mesh、path / physics 行为不作为主动产品目标，除非真实样本阻塞基础播放或导出，否则保持结构化诊断。
   - Spine 修改第一阶段不做骨骼或动画时间线编辑，只做组成文件替换装配：`Skeleton` 选择 `.skel / .json / .bytes` 等 skeleton 文件，`Atlas` 选择 atlas 文本文件，`Texture pages` 支持逐 page 图片替换，并提供文件夹批量匹配入口。组成文件替换区放在预览下方，并在默认窗口高度下使用受限内部滚动，避免挤压 Spine 动画画布。选择文件后先进入 Spine 编辑草稿并即时刷新预览；点击保存时再拆成目标为真实 `Texture2D / TextAsset` 组成资产的多条替换记录，共享同一批次和关联关系。Spine 组 `变更` 分段投影为一组 Spine 修改卡片，组成资产详情页仍展示各自真实记录并支持撤销 / 重做 / 删除。
   - Atlas region overlay 当前复用现有图片预览和棋盘格底图能力，在可解析 Texture2D page 上叠加 region 矩形；page 到 Texture2D 的匹配由 Application 详情 DTO 提供，Presentation 只通过预览管线加载图片载荷。普通 RGBA / 带透明通道的 Texture2D 预览载荷、多 atlas page 和常见独立 alpha companion 已进入 D3D / Win2D 主线：Presentation 只通过预览管线加载颜色图与 alpha 图载荷，按 atlas page / texture 资产名的 `_alpha / -alpha / .alpha / @alpha / [alpha] / _a` 等常见后缀做轻量匹配；解码阶段把颜色图与 alpha 图合成为 BGRA8 并统一转为 premultiplied alpha。D3D 后端按 page name 上传 shader resource，vertex batch 按连续 texture page 分批并保留 draw order，shader 采样 PMA texture 后乘以 slot / attachment tint alpha，并使用 PMA blend；Win2D 回退与基础 PNG 序列帧导出使用同一解码器和 premultiplied CanvasBitmap。当前仍不为完全无规律的 atlas page / alpha page 名称增加猜测匹配；这类情况先保留结构化诊断或样本门控，只有真实样本阻塞基础播放或导出时再做最小兼容。
   - `.skel` 二进制解析和动画播放当前通过官方 runtime adapter 输出中立 DTO；大量三角动画的长期 UI 承载采用默认 `D3D11 + SwapChainPanel + vertex batch renderer`，现有 Win2D 播放面只作为兼容回退，不作为高复杂 mesh 的性能主线。当前 D3D 后端已经覆盖面板、swap chain、顶点批量提交、Texture2D 预览载荷上传 / 采样、可复用动态 vertex / index buffer、Unloaded 资源释放、resize 防抖、device lost 一次重建、vertex batch 小窗口缓存、runtime playback session 当前帧渲染、渲染失败自动回退 Win2D，以及和 Win2D 回退共用的预览视口平移 / 滚轮缩放 / 重置；真实大量三角样本已验证 `60 FPS` 交互观感可接受，默认启用后仍需继续收集更多设备、内存占用、高刷新目标和设备恢复路径基线。

补充规则如下：

1. 富预览不是强制项；当资源无法解码或上下文不足时，必须稳定回退到结构化摘要，而不是显示空白。
2. `Material`、`Font`、`AnimationClip`、`GameObject`、`MonoBehaviour`、`AnimatorController` 当前先采用“半可视化摘要 / 轻量信息浏览”策略，不立即要求完整内容预览。
3. `AnimatorController` 当前不进入重型可视化主线，优先保留信息浏览和引用跳转；真实样本中 `m_AnimatorLayers / m_AnimatorParameters` 可为空，展示上不把这两个数组为空误判为整体不可预览。
4. 详情页中的预览区应额外承载结构化预览诊断，至少展示 `缓存状态 / 摘要回退原因 / detail`，避免失败原因只停留在日志中。
5. 预览内部若展示已解析资源（例如 `Material` 的 Shader / Texture 引用），应优先复用同一套已解析资源跳转目标与资产文档打开链路，不在具体预览控件中重新实现 Bundle 读取、缓存解析或资产定位。
6. 修改阶段的富预览以工作区当前有效内容为输入，但不得把有效预览结果写回原始资产详情、依赖图或导入索引；撤销替换后应重新投影回上一层有效内容或原始预览，重做替换后再投影到被恢复的替换来源。
7. Spine 资源组只能消费 Application 层输出的聚合 DTO、预览 sidecar 和现有图片载荷；Presentation 不得为了组装 Spine 关系直接读取资源包、遍历文件或解析 `.atlas / .skel`。
8. Spine GPU 播放面中的 D3D11 设备、swap chain、纹理上传和 vertex batch 都属于 Presentation 控件实现细节；不得把 D3D / WinUI 类型写入 Application DTO，也不得让官方 Spine runtime 对象越过 Infrastructure adapter 边界。

### 顶部反馈

顶部命令区与三栏工作区之间保留一个轻量状态摘要区，负责：

- 在状态标签前以轻量标签按钮提供 `新建工作区 / 打开工作区`
- 以标签化方式展示当前工作区、资源包数量、资源数量、当前工作区缓存占用和当前解密器；工作区缓存统计通过 Application 的聚合 usage 读取 `cache/bundles` 标准化资源包与 `cache/previews` 预览缓存，不再在工作台顶部显示已登记工作区数量

主工作区内的即时反馈统一采用顶部轻量浮动提示，负责：

- 工作区加载成功
- 提取、替换、撤销等关键结果
- 高价值失败提示

顶部命令区中的 `批量提取` 不再导航到批处理页，而是打开当前工作区内的轻量独立批量提取窗口。该窗口展示当前工作区资源包列表，允许选择资源包范围，并按当前勾选资源包动态生成 `全部 / Texture2D / Sprite / Spine` 等可导出类别及候选数量；点击开始后再选择输出目录，或勾选“导出到工作区提取目录”直接使用工作区数据目录下的提取目录，随后通过统一后台任务 `BatchExtraction` 执行。详细交互、Application 契约和测试建议见 [workspace-batch-extraction-dialog.md](workspace-batch-extraction-dialog.md)。

## 5. 标签页策略

当前阶段正式采用“类似 VS Code 的资源包标签页”策略。

推荐交互规则如下：

1. 单击左侧资源包节点：
   直接打开该资源包的标签页；如果该资源包已经有标签页，则直接激活已有标签页。
2. 左侧资源包搜索按钮：
   只负责展开或收起搜索框，不再承担打开标签页语义。
3. 左侧资源包列表收缩按钮：
   在完整 Explorer 列表和摘要窄条之间切换；收缩时同步关闭搜索框。

补充规则如下：

1. 同一工作区内，同一资源包只保留一个标签页实例。
2. 单击资源包列表是当前默认打开方式，不再额外提供“新标签页”按钮。
3. 关闭标签页只移除页面级浏览状态，不影响工作区中的真实数据和变更队列。

## 6. 状态归属

- 已加载资源包集合
- 变更队列
- 任务列表
- 日志中心

应用级工作区目录状态包括：

- 当前活动工作区

页面级标签页状态只包括：

- 当前标签页对应的资源包
- 当前搜索关键字
- 当前类型筛选

- 当前主选中资源

## 9. 实现准线

后续进入实现时，默认按以下准线执行：

- 主窗口负责主工作流和统一保存入口。
- 控制台由第一导航入口在无工作区时承载，不额外占用独立一级导航项。
- 主工作区继续保持单窗格三栏，不再回到双窗格主流。
- 资源包浏览扩展能力统一通过标签页实现，不再重新引入子窗口。
- 多工作区当前先稳定在上下文与元数据设计层，不急于一次性铺完整切换 UI。
- 所有修改统一进入工作区变更队列。
- 当前编辑动作统一收敛在主窗口检查器。
