# AssestBundleTools UI 收敛方案 V3

## 1. 文档目的

本文档用于记录当前阶段已经正式收敛的 UI 方案，作为后续开发、验收与讨论的统一基线。

当前文档只保留已经确认的主工作流，不再保留已经被淘汰的子窗口方案。

## 2. 最终结论

当前 UI 采用“控制台页 + 主窗口单窗格三栏工作台 + 资源包标签页 + 多工作区上下文预留”的方案。

核心原则如下：

1. 主工作流固定在主窗口完成，不再为资源包浏览引入子窗口。
2. 左侧负责资源包浏览与搜索，中间负责标签页和资产列表，右侧负责资源详情与编辑入口。
3. 详细日志集中在“设置与诊断”，主工作区只保留轻量 toast 反馈。
4. 所有修改统一归属到工作区会话，不直接覆盖原始文件。
5. 工作区上下文按 IDE 式模型演进，允许应用登记多个工作区，但主任务始终绑定当前活动工作区。
6. 标签页只承载页面级浏览状态，工作区数据仍是唯一事实来源。
7. 控制台页默认在应用启动阶段显示；进入工作区后可继续停留在工作台，也允许通过显式按钮返回控制台。

## 3. 应用结构

应用外壳继续使用 `NavigationView`。

其中一级导航当前保留三个稳定入口位：

- 第一入口位：无活动工作区时显示“控制台”，进入工作区后显示“工作台”
- 批处理任务
- 设置与诊断

其中第一入口位复用同一个 `NavigationViewItem` 承载两种窗口态：

- 控制台态：默认在应用刚启动时显示，也允许从工作台显式返回
- 工作台态：进入活动工作区后显示正式工作台

当前控制台页承担以下稳定职责：

- 提供 `新建工作区 / 打开工作区 / 打开最近工作区` 三个快速入口
- 以固定高度面板展示 `工作区列表` 与 `最近操作`
- `工作区列表` 与 `最近操作` 各自使用卡片内滚动，不再让整页纵向滚动
- 允许从最近工作区列表删除登记记录
- 当“启动时恢复上次工作区”设置开启且上次活动工作区仍可用时，允许启动后直接恢复到正式工作台
- 新建 / 打开工作区时使用单一可视化配置面板，而不是连续目录选择器
- 工作区向导中允许单独配置工作区名称，并把该名称保存到工作区元数据和最近工作区列表
- 新建工作区时先创建空工作区，不再要求预先指定 AB 来源目录；资源后续通过拖拽或导入入口加入
- 从控制台再次打开最近工作区时，支持三种设置策略：默认复用当前窗口、默认新建窗口、每次询问
- 当策略为“默认新建窗口”且目标工作区已在某个主窗口中打开时，直接激活已有窗口，不再重复创建新窗口

当前工作台页面由 `BundleExplorerPage` 承载，并在状态标签前置动作区同步承担以下工作区入口职责：

- `新建工作区` 复用与控制台页一致的可视化工作区向导
- `打开工作区` 复用已有工作区打开向导
- `返回控制台` 允许当前窗口回到控制台页，而不强制关闭现有活动工作区上下文
- 页面直接从导航进入时优先恢复当前活动工作区，而不是回退到独立的示例数据入口

## 4. 工作台最终结构

当前工作台页面采用“三栏固定工作区 + 顶部命令区 + 顶部浮动提示”的结构。

### 左侧

左侧为资源包列表，负责：

- 显示当前工作区中已加载的资源包分组
- 提供 VS Code 风格的 explorer 式浏览体验
- 在列表标题栏提供 `文件导入 / 目录导入` 入口
- 支持把资源包文件或目录直接拖到左侧资源包列表区域触发导入提示层
- 提供资源包搜索和过滤入口
- 作为资源包标签页的直接打开入口
- 资源包项支持右键上下文菜单，至少提供 `打开所在位置` 与 `从工作区移除`
- 支持收缩为摘要窄条，以释放更多横向空间给资产列表与资源详情
- 当工作区尚未导入任何资源包时，显示“空工作区”专用空状态提示，而不是误导性的“未打开标签页”提示

当前阶段不再显示独立依赖树主窗格。

但工作台右侧检查器应提供单独的“依赖”页签，以列表方式承载：

- 资产级依赖
- 反向引用
- 依赖闭包
- Bundle 外部依赖

补充规则如下：

1. 资产依赖项应展示友好资源名、所属资源包摘要、`PathId` 与必要的类型信息。
2. 依赖闭包项应额外展示闭包深度，便于判断某个资源是直接依赖还是间接依赖。
3. Bundle 外部依赖应优先展示友好名称和依赖类型；对于 `archive:/CAB-xxx/CAB-xxx` 这类引用，如当前工作区能反查到对应资源包，则标题优先显示具体 `xxx.ab` 文件名，并在副标题保留 `CAB-*` 标识，同时把原始引用路径作为补充信息保留。
4. 友好路径解析优先采用 Unity `m_Container` 路径，缺失时再回退到 `SerializedFileName / 资产类型 / PathId` 组合摘要，避免同名资源在依赖页中难以区分。

同一套 `文件导入 / 目录导入` 入口应同步承载到批处理页和“设置与诊断”页的活动工作区摘要区，避免后续真实导入链路在不同页面出现分叉。
工作台中的拖拽接收范围当前应限制在左侧资源包列表区域，不扩散到整页，给后续资产列表拖拽操作保留清晰边界。

左栏收缩后的摘要窄条当前保留：

- `文件导入 / 目录导入` 的文字标签按钮
- 当前可见资源包总数
- 当前可见分组数量
- 当前选中资源包的短缩写与完整悬浮提示

当左栏收缩时，中间“资产列表”和右侧“资源详情”需要均分释放出来的横向区域。

### 中间

中间区域由“标签页栏 + 当前活动资产窗格”组成，负责：

- 显示当前已打开的资源包标签页
- 显示当前活动资源包的资产列表
- 提供搜索、类型筛选和本地显示筛选
- 支持鼠标友好的多选
- 在多选状态下显示列表内快捷操作

当前收敛规则如下：

1. 资产列表默认保持单表格浏览样式。
2. 资产列表支持 `Ctrl / Shift` 扩展多选。
3. 当资产列表选中数量大于 1 时，在列表头部下方显示快捷操作条。
4. 当前快捷操作条只保留“提取选中”。
5. 单资源提取仍保留在右侧检查器中。
6. 每个资源包标签页都应独立保存资产列表的搜索条件、类型筛选、本地显示筛选和当前选中资源。
7. 切换资源包标签页时，资产列表应恢复到该标签页上次浏览状态，不因切换而丢失当前选中资源。
8. 应用重启后，如果工作区恢复了已打开标签页，则活动标签页的资产列表也应自动恢复到上次选中的资源。
9. 每个资源包标签页下的右侧资产详情区应再提供一层“资产文档标签”，用于并行保留多个资源的详情上下文，而不是只复用单一检查器实例。
10. 资产文档标签需要独立保存当前资源、当前检查器页签和页面级候选状态；切换资源包标签页或重启应用后都应尽量恢复。
11. 资源列表的搜索、类型筛选和本地显示筛选只影响当前列表结果与焦点恢复，不应直接关闭已经打开的资产文档标签；即使当前筛选结果为空，右侧已打开的资产详情标签也应继续保留，同时列表也不应自动把焦点跳到筛选结果第一项。
12. 当筛选变化并未改变当前激活的资产文档标签时，右侧详情内容应直接复用现有状态，不重复触发详情查询、图片预览重载或详情页滚动位置重置。
13. 资源包标签与资产文档标签都应支持右键菜单，至少提供 `关闭其他` 与 `关闭全部`，并保持关闭后的焦点落点可预期。

### 右侧

右侧为资源详情检查器，负责：

- 外层承载当前资源包下已打开的资产文档标签
- 详情信息与预览承载
- 工作区替换来源与状态
- 变更摘要
- 固定在底部的快速操作按钮区

当前编辑入口继续统一收敛在右侧检查器，不分散到其他区域。

右侧结构约束补充如下：

1. 外层 `TabView` 用于切换不同资产文档。
2. 内层检查器当前收敛为 `详情 / 依赖 / 替换 / 变更` 四页签；其中“详情”页统一承载预览画面、基础信息、预览补充信息与预览诊断，避免旧版“概览 / 预览”之间的信息重复。其视觉上应采用比外层文档标签更轻的分段切换样式，避免与上层大标签混淆；字体、高度和选中反馈都应明显更轻，作为次级内容切换而不是第二层文档标签。
3. 资产文档标签归属当前资源包标签页管理，不单独升级为跨工作区或跨页面的全局窗口模型。
4. 内层分段切换条需要保持紧凑，与上方资产文档标签和下方详情内容之间的留白应控制在次级导航应有的密度，不应出现明显断层。

预览区后续按以下多形态承载演进：

1. 图像预览
   - 用于 `Texture2D`、`Sprite`，后续扩展到 `SpriteAtlas`。
2. 文本预览
   - 用于 `TextAsset`、`Shader`。
3. 音频预览
   - 预留给 `AudioClip`，目标形态为 `播放 / 暂停 + 时长 + 波形或幅度摘要`。
4. 模型预览
   - 预留给 `Mesh`，目标形态为 `静态 3D 视口 + 旋转 / 缩放 / 重置`。
5. 结构化摘要预览
   - 继续作为 `Material / Font / AnimationClip / GameObject / MonoBehaviour / AnimatorController` 等类型的安全回退。

补充规则如下：

1. 富预览不是强制项；当资源无法解码或上下文不足时，必须稳定回退到结构化摘要，而不是显示空白。
2. `Material`、`Font`、`AnimationClip` 当前先采用“半可视化摘要”策略，不立即要求完整内容预览。
3. `GameObject`、`MonoBehaviour`、`AnimatorController` 当前不进入重型可视化主线，优先保留信息浏览和引用跳转。
4. 详情页中的预览区应额外承载结构化预览诊断，至少展示 `缓存状态 / 摘要回退原因 / detail`，避免失败原因只停留在日志中。

### 顶部反馈

顶部命令区与三栏工作区之间保留一个轻量状态摘要区，负责：

- 展示当前阶段说明
- 在状态标签前以轻量标签按钮提供 `新建工作区 / 打开工作区`
- 以标签化方式展示当前工作区、已登记工作区数、已打开标签页数、资源包数量、资源数量、来源路径和当前解密器

主工作区内的即时反馈统一采用顶部轻量浮动提示，负责：

- 工作区加载成功
- 提取、替换、撤销等关键结果
- 高价值失败提示

### 日志位置

详细日志统一放在“设置与诊断”页面，负责：

- 工作区加载记录
- 关键操作记录
- 异常与失败信息
- 后续导出诊断数据

## 5. 标签页策略

当前阶段正式采用“类似 VS Code 的资源包标签页”策略。

推荐交互规则如下：

1. 单击左侧资源包节点：
   直接打开该资源包的标签页；如果该资源包已经有标签页，则直接激活已有标签页。
2. 左侧资源包搜索按钮：
   只负责展开或收起搜索框，不再承担打开标签页语义。
3. 左侧资源包列表收缩按钮：
   在完整 Explorer 列表和摘要窄条之间切换；收缩时同步关闭搜索框。

补充规则如下：

1. 同一工作区内，同一资源包只保留一个标签页实例。
2. 单击资源包列表是当前默认打开方式，不再额外提供“新标签页”按钮。
3. 关闭标签页只移除页面级浏览状态，不影响工作区中的真实数据和变更队列。

## 6. 状态归属

状态统一归属于工作区，而不是单个页面控件。

工作区级状态包括：

- 已加载资源包集合
- 变更队列
- 任务列表
- 日志中心

应用级工作区目录状态包括：

- 当前活动工作区
- 已登记工作区摘要列表
- 最近激活顺序
- 后续将接入的固定项与恢复元数据

页面级标签页状态只包括：

- 当前标签页对应的资源包
- 当前搜索关键字
- 当前类型筛选
- 当前显示筛选
- 当前主选中资源

## 7. MVP 范围

当前阶段 MVP 已收敛为以下内容：

- `NavigationView` 应用外壳
- 控制台页
- 工作台主页面（当前由 `BundleExplorerPage` 承载）
- 主窗口单窗格三栏工作区
- 资源包标签页浏览机制
- 左侧资源包列表收缩为摘要窄条
- 资产列表多选与列表内“提取选中”快捷操作
- 顶部轻量 toast 反馈
- 设置与诊断中的详细日志中心
- 多工作区上下文骨架
- 单资源提取命令骨架
- 文件替换候选与应用骨架
- 工作区替换候选选择、应用与撤销骨架
- 资源详情中的替换状态与变更摘要
- 批处理页中的当前工作区变更统计与最近变更列表
- 批处理页中的保存前摘要、建议输出目录与资源包输出预览
- 工作台到批处理页的入口跳转

当前阶段不纳入：

- 子窗口浏览
- 主界面双窗格对比
- 依赖树主工作流
- 复杂跨标签页拖拽替换
- 真实文件导出
- 批量提取与保存摘要弹窗
- 全类型真实预览器
- 工作区切换器完整 UI

## 9. 实现准线

后续进入实现时，默认按以下准线执行：

- 主窗口负责主工作流和统一保存入口。
- 控制台由第一导航入口在无工作区时承载，不额外占用独立一级导航项。
- 主工作区继续保持单窗格三栏，不再回到双窗格主流。
- 资源包浏览扩展能力统一通过标签页实现，不再重新引入子窗口。
- 多工作区当前先稳定在上下文与元数据设计层，不急于一次性铺完整切换 UI。
- 所有修改统一进入工作区变更队列。
- 当前编辑动作统一收敛在主窗口检查器。
