# 应用更新与 GitHub Release 发布契约

## 1. 文档职责

本文定义版本来源、发布产物、安装/便携更新通道、应用内更新流程和发布门禁。某个版本实际包含的变化只写在对应的[版本说明](../releases/README.md)，本文不维护逐版本验收流水。

## 2. 发布结论

- 版本由 `v<SemVer>` Git tag 和 MinVer 统一生成。
- GitHub Release 是公开发布源和默认更新源。
- 更新框架使用 Velopack，不自研替换协议。
- x86、x64、ARM64 分别发布 Portable ZIP 和 Installer MSI。
- 应用正常启动后后台检查一次更新；关于页提供手动检查和版本日志入口。
- 下载、应用和重启必须由用户确认，并在活动工作区任务安全结束后执行。
- 安装模式、架构和更新通道不可串包。

## 3. 版本与发布说明

- tag、程序集版本、包版本、Release 标题和 feed 版本必须一致。
- 正式 tag 必须存在 `docs/releases/<tag>.md`，缺失时发布失败。
- Release 正文和应用内更新详情使用同一 Markdown 文件，不另写第二份摘要。
- 已发布版本说明视为不可变档案；补充说明应通过新版本或 Release 附注处理。

详细规则见 [docs/releases/README.md](../releases/README.md)。

## 4. 产物矩阵

每个架构至少产生：

| 产物 | 用途 |
| --- | --- |
| Portable ZIP | 免安装分发 |
| Installer MSI | 交互式安装 |
| full package / feed | Velopack 更新 |
| SHA-256 清单 | 下载完整性核对 |

发布脚本必须检查 PE 架构、版本、必要运行文件、内置 codec、Monaco 离线资源、应用图标和 feed 元数据。缺少任何必需资源时不得公开 Release。

## 5. MSI 与 Portable

### MSI

- 提供欢迎页、MIT 许可确认、当前用户/所有用户、安装目录和桌面快捷方式选项。
- 当前用户默认安装到 `%LocalAppData%`，不要求管理员权限。
- 所有用户默认安装到 `Program Files`，由 Windows 请求提升。
- 卸载不删除用户工作区、缓存、插件和偏好。

### Portable

- 解压后可直接运行，不依赖开发证书。
- 更新后仍保持 portable 模式，不迁移成安装版。
- 应用目录与工作区数据目录必须分离。

未签名包可能触发 SmartScreen 或组织策略。代码签名是发布加固项，但不能被描述为用户需要自行安装的证书。

## 6. 更新流程

### 启动检查

- Shell 首帧后调度后台检查，不阻塞启动。
- 失败保持静默并写结构化诊断。
- 同架构多进程共享检查节流，避免重复请求。
- 缓存只复用展示结果；下载前重新取得可用的更新信息。

### 手动检查

- 关于页显示当前版本、最新结果、下载进度、取消和待重启状态。
- 手动失败给出本地化反馈，并允许复制诊断。
- 更新确认窗口显示目标版本对应的中文 Release Notes；英文内容可选。

### 下载与应用

- 下载到应用更新目录并验证框架元数据与哈希。
- 活动导入、替换、导出、草稿保存或其他实例存在时不得强制退出。
- 应用确认后由 Velopack `Update.exe` 在进程退出后替换并重启。
- 失败必须保留当前可运行版本，不触碰工作区和用户插件。

## 7. 分层边界

### Application

- 定义版本、架构、安装模式、更新状态和稳定错误。
- 编排检查、下载、取消和应用前阻断。
- 不依赖 GitHub JSON、Velopack 或 WinUI。

### Infrastructure

- 适配 Velopack/GitHub，处理 feed、下载、哈希和更新进程。
- 返回结构化数据与原始诊断，不生成用户提示。

### Presentation

- 调度启动检查，显示关于页和更新确认。
- 协调窗口/任务安全退出，不直接请求 GitHub 或替换文件。

### CI 与发布脚本

- 使用 tag 触发三架构矩阵。
- 构建、测试、打包、校验资产名与 digest 后再公开 Release。
- 不允许手工上传一组未经过同样门禁的“等价”正式包。

## 8. 安全与隐私

- 更新源使用 HTTPS，下载结果执行完整性检查。
- Release API/下载失败不降低应用现有功能。
- 不把工作区路径、插件配置或诊断日志上传到更新服务。
- 更新不能覆盖 `%LocalAppData%/AssestBundleTools` 中的工作区外用户数据。
- 官网镜像或备用 feed 必须保持相同的架构、版本和哈希契约。

## 9. 发布门禁

### 自动化

- 五层测试和本地化/架构 guardrail 通过。
- 三架构 publish 和 PE 架构检查通过。
- Portable、MSI、full package、feed 和 checksum 齐全。
- Release Notes 存在且与 tag 一致。
- Monaco、内置 codec、图标和运行时依赖存在于发布产物。

### 实机

- 当前用户 MSI 安装、启动、更新和卸载。
- 所有用户 MSI 的 UAC、自定义目录和快捷方式。
- Portable 解压启动与跨版本更新。
- x86、x64、ARM64 至少在对应系统或可靠设备矩阵验证。
- 断网、下载中断、校验失败、目录只读时旧版仍可启动。
- 更新后工作区、偏好、日志、缓存和用户插件保持可用。

未完成某项实机门禁时，只能说明对应能力尚在验证，不能在产品文案中宣称已覆盖全部环境。

## 10. 延后范围

- 发布者代码签名与证书轮换。
- preview/stable 独立通道。
- 官网 feed 镜像和灾备切换。
- 更细的增量包与带宽优化。

这些增强不得改变当前版本、架构隔离和失败保留旧版的基本契约。
